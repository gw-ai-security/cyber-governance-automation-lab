# Phase 8.2 — Power BI Project Scaffold

## Status

**PHASE 8.2 COMPLETE — VERSION-CONTROLLED POWER BI PROJECT SCAFFOLD CREATED**

Phase 8.2 creates the source-controlled Power BI project artifact that later Phase 8 work packages will extend. It deliberately stops before data ingestion, semantic-model relationships, DAX measures, or report visuals.

The project artifact lives under:

```text
powerbi/CyberGovernanceDashboard/
```

and was created in Power BI Desktop with the Power BI Project (PBIP), enhanced report metadata (PBIR), and TMDL semantic-model formats enabled.

## 1. Purpose

Phase 8.0 froze the reporting contract and KPI semantics. Phase 8.1 fixed the deterministic canonical reporting baseline. Phase 8.2 now establishes the version-controlled Power BI container without prematurely implementing Phase 8.3+ behavior.

The dependency sequence is therefore:

```text
Phase 8.0
Reporting/KPI contract
        ↓
Phase 8.1
Canonical reporting baseline
        ↓
Phase 8.2
PBIP + PBIR + TMDL project scaffold
        ↓
Phase 8.3
Load and type curated CSV sources
```

## 3. PBIP Root Contract

`CyberGovernanceDashboard.pbip` is the project entry point.

Its report artifact path resolves to:

```text
CyberGovernanceDashboard.Report
```

The PBIP file is intentionally small and contains project-level metadata rather than report business logic.

## 4. PBIR Report Contract

The report uses the enhanced report metadata format.

`CyberGovernanceDashboard.Report/definition.pbir` references the semantic model by relative path:

```text
../CyberGovernanceDashboard.SemanticModel
```

This establishes a repository-relative Report → Semantic Model dependency and avoids a machine-specific absolute path.

The `definition/` folder contains the source-controlled report definition generated by Power BI Desktop.

At Phase 8.2 the report is intentionally blank. The generated initial page is only scaffold metadata; it is not accepted as one of the final Phase 8 report pages yet.

## 5. TMDL Semantic Model Contract

The semantic model uses the TMDL source format under:

```text
CyberGovernanceDashboard.SemanticModel/definition/
```

At Phase 8.2 the model contains only the initial Power BI model metadata and culture configuration.

Current culture metadata is:

```text
de-DE
```

No Phase 8 reporting tables have been loaded yet.

Specifically, Phase 8.2 does **not** contain:

```text
ControlStatus table
DataQualityIssues table
Power Query source expressions
DataRoot parameter
model relationship
DAX governance measures
DAX Data Quality measures
DAX process/reminder measures
final dashboard visuals
```

These remain later work packages.

## 6. Platform Metadata

Power BI generated `.platform` files for both the Report and Semantic Model artifacts.

They contain artifact type, display name, version metadata, and generated logical IDs used by the project format.

These generated logical IDs are project artifact metadata. Phase 8.2 does not contain Power BI Service workspace IDs, tenant IDs, credentials, tokens, gateway configuration, or production deployment bindings.

## 7. Git Boundary

Phase 8.2 corrected the Power BI ignore boundary so source-control-safe editor metadata can remain versioned while local model state stays private.

The repository ignores:

```gitignore
**/.pbi/localSettings.json
**/.pbi/cache.abf
```

Therefore the following remain machine-local:

```text
Report/.pbi/localSettings.json
SemanticModel/.pbi/localSettings.json
SemanticModel/.pbi/cache.abf
```

The following is intentionally versioned:

```text
SemanticModel/.pbi/editorSettings.json
```

This file contains model editor behavior settings rather than cached model data or machine-local connection state.

The repository does not use a blanket `.pbi/` ignore rule because that would also suppress the source-control-safe editor settings file.

## 8. Privacy and Security Acceptance

The Phase 8.2 artifact contains no reporting data and no operational Microsoft 365 data.

The scaffold contains no:

- canonical CSV contents,
- private Phase 7 snapshot contents,
- owner e-mail addresses from operational data,
- evidence comments,
- OneDrive paths,
- tenant identifiers,
- workspace identifiers,
- data-source credentials,
- access tokens,
- gateway credentials.

The Power BI project therefore remains inside the public portfolio evidence boundary.

## 10. Repository Acceptance Checks

Phase 8.2 acceptance requires all of the following:

- PBIP project entry point exists,
- PBIR report definition exists,
- TMDL semantic-model definition exists,
- Report references Semantic Model through a repository-relative path,

The accepted repository structure satisfies these conditions.
