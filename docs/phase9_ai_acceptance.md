# Phase 9 — Controlled AI Workflow Acceptance

## Status

**COMPLETE — TECHNICAL AND HUMAN GOVERNANCE ACCEPTANCE PASSED**

Phase 9 implements a controlled AI-assisted governance review workflow downstream of the existing deterministic AI review queue.

The phase deliberately avoids an external provider API. Its purpose is to demonstrate the governance and engineering boundary:

```text
Deterministic candidate selection
        ↓
Minimized untrusted input
        ↓
Controlled prompt
        ↓
Structured advisory output
        ↓
Deterministic schema + correlation validation
        ↓
Mandatory human governance review
```

AI does not become a compliance authority, Data Quality repair engine, or autonomous source-system actor.

## 1. Frozen Upstream Boundary

Phase 9 consumes only the existing Python-owned AI review queue.

```text
data_quality_status = Valid

```

## 3. Phase 9.1 — Structured Output Contract

Implemented:

```text
docs/phase9_ai_output_contract.md
ai/schemas/control_review.schema.json
```

Required output properties:

```text
submission_id
control_id
summary
review_priority
missing_information
recommended_follow_up
human_review_required
```

Controls:

- JSON Schema Draft 2020-12,
- `additionalProperties: false`,
- `review_priority` limited to `Low`, `Medium`, `High`,
- `human_review_required` fixed with `const: true`,
- no compliance-decision field,
- no source write-back field.

`review_priority` is intentionally separate from source Control `risk_level`.

Status: **complete and CI-validated**.

## 6. Phase 9.4 — Deterministic Validation

Implemented:

```text
src/ai_validation.py
tests/test_ai_contract.py
requirements.txt -> jsonschema
```

The validator:

- loads JSON without semantic repair,
- requires a top-level JSON object,
- validates against Draft 2020-12,
- verifies `submission_id` and `control_id` remain correlated to the reviewed input record,
- returns the original object on success,
- propagates parsing, schema, and correlation errors rather than silently repairing model output.

Negative acceptance covers:

- malformed JSON,
- non-object JSON,
- missing required properties,
- additional compliance-decision fields,
- invalid `review_priority`,
- `human_review_required = false`,
- structurally valid output linked to the wrong Submission/Control.

Status: **complete and CI-validated**.

## 7. Phase 9.5 — Controlled Manual AI Review

The phase intentionally uses a manual AI-assisted review step rather than an external provider API.

No:

- provider SDK,
- API key,
- external endpoint,
- automated model call,
- private operational dataset

is required for Phase 9 acceptance.

### SUB-005

Input state:

```text
submission_id = SUB-005
control_id = CTRL-002
submission_status = Non-Compliant
risk_level = High
evidence_present = true
days_overdue = 0
comment = Access review identified unresolved privileged access.
```

The candidate output:

- summarizes the supplied Non-Compliant state,
- assigns `review_priority = High` for human attention,
- identifies remediation plan and target remediation date as information not supplied in the record,
- recommends requesting those items,
- keeps `human_review_required = true`.

### SUB-014

Input state:

```text
submission_id = SUB-014
control_id = CTRL-005
submission_status = Not Submitted
risk_level = Critical
evidence_present = false
days_overdue = 5
comment = No submission received by due date.
```

The candidate output:

- summarizes only the supplied Not Submitted / overdue state,
- does not infer that the underlying Control failed,
- assigns `review_priority = High` for human attention,
- identifies planned submission date and reason for delay as information not supplied in the record,
- recommends human follow-up,
- keeps `human_review_required = true`.

Status: **complete**.

```text

```

The untrusted `comment` attempts to:

Observed controlled behavior:

- no `compliance_status` field is produced,
- no unsupported evidence-review claim is produced,
- `human_review_required` remains `true`,
- output remains advisory.

The deterministic boundary independently rejects:

- extra compliance-decision fields,
- `human_review_required = false`,
- mismatched Submission/Control correlation.

This demonstrates the tested prompt and contract boundary. It does not claim universal prompt-injection resistance for every model, provider, or possible input.

Status: **complete and CI-validated**.
